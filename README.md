# pushwatch

Мини-приложение (Tauri 2 + Svelte 5) для отслеживания незапушенных коммитов
в большом количестве git-репозиториев на локальной машине — и сводки по
всем машинам. Живёт в трее (менюбаре на macOS), показывает окно по клику.

## Что показывает

- **↑N** — локальная ветка опережает свой upstream (забыл запушить коммиты)
- **⇅N/M** — ветка расходится с upstream (ahead и behind): нужен `pull --rebase`
- **~N / ?N** — незакоммиченные изменения / untracked файлы
  (OS-мусор — `.DS_Store`, `Thumbs.db`, `desktop.ini`, `._*` — не считается)
- **∅ ветка** — ветка ни разу не запушена (нет upstream)
- **no remote** — remote не настроен вообще: репозиторий живёт только на этой машине
- **✕ ветка** — upstream настроен, но remote-ветка удалена
- **orphan N** — коммиты HEAD, не видимые ни на одном remote и ни на одной ветке
  (force-push, detached HEAD)
- **detached** — HEAD вне ветки

Ветки в деталях отсортированы «интересные вперёд» (с незапушенными
коммитами — выше), текущая ветка всегда первая. Push для ветки,
синхронизированной с upstream, заблокирован (нечего пушить).

Трей-индикатор: зелёный — всё запушено, жёлтый — только изменения и
незапушенные ветки, красный — есть реально незапушенные коммиты, серый —
ошибки. На macOS в менюбаре дополнительно счётчик проблемных репо.

## Действия

- **Push** на каждую ветку: всегда явная команда —
  `git push <remote> -- <branch>` (для непушенных — `git push -u`),
  target-remote из upstream ветки или `git remote`. Credential-промпты
  отключены (`GIT_TERMINAL_PROMPT=0`) — push не зависает, при проблемах
  с аутентификацией быстро падает с понятной ошибкой. Аутентификация —
  через системный git (ssh-agent / credential manager), как в терминале.
- **Запушить всё** — очередь из всех веток с незапушенными коммитами,
  последовательно, с прогрессом в шапке и сводкой. Diverged-ветки
  пропускаются (нужен pull).
- **Fetch** на репо и **Fetch всё** (`git fetch --all --prune`,
  параллельно по 4) — обновляет ahead/behind до реальных.
- **auto_fetch** в настройках: fetch перед каждым фоновым сканом.
- Клик на файл в списке изменений — показать в файловом менеджере.
- **Системные уведомления** при появлении незапушенных коммитов и когда
  всё снова запушено.

## Автоматика

- Фоновый скан по таймеру + при фокусе окна + кнопкой.
- **fs-watcher**: изменение `.git` на диске (коммиты, ветки, checkout)
  триггерит перескан через 3 с — трей реагирует почти мгновенно.
- **История** (вкладка): все сканы, пушы и fetch с результатами,
  `history.jsonl` с ротацией.

## Сводка по машинам

В настройках укажите **папку синхронизации** (Syncthing / iCloud /
приватный git-репозиторий). Каждый скан кладёт туда
`snapshot-<machine_id>.json`, pushwatch читает все файлы и показывает
вкладку «Машины»: статус каждой машины, чьи репо с незапушенными
коммитами, устаревшие снапшоты (>2 суток) помечены. Push на чужой машине
из сводки не выполняется — статусы других машин read-only.

## Тема

Настройки → Тема: **Авто** (следует за системной), **Светлая**, **Тёмная**.
Смена применяется мгновенно; «Авто» реагирует на переключение системы на
лету.


## Запуск из исходников

Требуется: Node 18+, Rust (stable), git в PATH.

```bash
npm install
npm run tauri dev      # режим разработки
npm run tauri build    # релиз: .app / .dmg (macOS) или .msi (Windows)
```

Если сборка .dmg падает с ошибкой AppleScript/Finder (частое явление в
headless/CI-средах), собирайте только бандл приложения:

```bash
npm run tauri build -- --bundles app
```

### macOS

Ничего сверх стандартного (Xcode CLT). Приложение — «менюбарное»: без иконки
в доке (`ActivationPolicy::Accessory`), окно закрывается в трей (не выходит
из приложения), повторный запуск поднимает существующий инстанс.

### Windows

- [Rust MSVC toolchain](https://rustup.rs/) + Visual Studio Build Tools
- git должен быть в PATH (обычно установлен при работе с репозиториями;
  если нет — поставьте [Git for Windows](https://git-scm.com/download/win))
- WiX Toolset нужен только для сборки .msi (`npm run tauri build`)

## Конфигурация

Файлы лежат в стандартных папках приложения:

- Настройки: `config.json` в app config dir
  (macOS: `~/Library/Application Support/com.pushwatch.app/`)
- Снапшот последнего скана: `snapshot.json` в app data dir
  (macOS: `~/Library/Application Support/com.pushwatch.app/`,
  Windows: `%APPDATA%\com.pushwatch.app\`)

Запись конфига атомарная (temp + rename). Повреждённый config.json не
затирается молча: он сохраняется рядом как `config.json.bak-<timestamp>`,
а приложение стартует с дефолтами — корни и настройки восстанавливаются
из bak-файла вручную.

В настройках окна: корневые папки для рекурсивного поиска репозиториев,
исключённые имена папок, дополнительные репозитории вне корней, скрытые
репозитории, интервал фонового скана, глубина поиска, автозапуск.

## Синхронизация между машинами (задел на будущее)

`snapshot.json` — переносимый контракт: стабильный `machine_id` + имя
машины + полный список статусов. Сейчас он просто пишется на диск.
Чтобы получить сводку по всем машинам, достаточно синхронизировать папки
со снапшотами (Syncthing / iCloud / приватный git-репозиторий) и читать
их агрегатором — формат уже мульти-машинный с первого дня.

## Тесты

```bash
cd src-tauri
cargo test
```

44 теста: парсеры porcelain v2 (включая пути файлов, UTF-8 имена веток,
remote-имена со слэшами) / for-each-ref, движок статуса на реальных
временных git-репозиториях (ahead, diverged, dirty+список файлов,
no-upstream, no-remote, upstream-gone, detached+orphan, unborn HEAD,
битые репо, дедупликация Orphan/Ahead, OS-мусор не считается dirty,
сортировка веток interesting-first), сканер (вложенные репо, worktrees,
submodules-скип, исключения, скрытия с неканоническими путями, warnings),
конфиг (tilde, полный roundtrip с темой, карантин битого файла),
argv-конструктор push, очередь push_all, история (roundtrip, ротация,
битые строки).

## Архитектура (кратко)

- `gitbin.rs` — запуск системного git (`--no-optional-locks`, `LC_ALL=C`,
  `core.quotepath=false` — детерминированный вывод)
- `parsers.rs` — парсинг `git status --porcelain=v2 --branch` и
  `for-each-ref` (чистые функции)
- `engine.rs` — статус репозитория за 3–4 локальных вызова git
- `scanner.rs` — walkdir-поиск `.git` (worktree да, submodule нет)
- `scan.rs` — параллельный скан (rayon) + события в UI по мере готовности
- `push.rs` — стриминг вывода `git push` в окно
- `tray.rs` — иконка/меню трея, счётчик в менюбаре (macOS)
- `state.rs` / `config.rs` — конфиг и снапшот в JSON
- фронтенд: Svelte 5 (runes), `src/lib/store.svelte.ts` — единый стор
